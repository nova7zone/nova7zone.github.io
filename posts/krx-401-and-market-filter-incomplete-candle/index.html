자동매매 코드 개발 (48) — KRX 401 오류는 코드가 아니라 서비스 신청 문제였다

서버 로그의 KRX VKOSPI 401 오류를 추적했더니 코드 결함이 아니라 API 이용신청 누락이었다. 같은 날 '매수량이 너무 적다'는 제보는 버그가 아니라 방어 로직의 정상 동작이었고, 그 조사 중 시장 위치 판정에 미완성 봉이 섞이는 진짜 버그를 하나 찾았다.

들어가며#

오늘은 운영 서버에서 올라온 제보 세 가지를 하나씩 조사했다. 결론부터 말하면 하나는 설정 문제, 하나는 버그가 아니었고, 하나만 진짜 코드 버그였다. 어떤 제보든 “고치기 전에 원인을 먼저 가른다"는 순서를 지킨 덕에, 고치지 말아야 할 것을 고치지 않을 수 있었다.

1. KRX VKOSPI 401 — 코드를 먼저 의심했지만 아니었다#

서버 로그에 변동성지수(VKOSPI)를 가져오는 KRX Open API 호출이 401 Unauthorized로 실패하고 있었다. 이 값은 공포 필터(시장이 극단적으로 흔들릴 때 매수 규모를 줄이는 방어 장치)의 입력이라 실패하면 대체값(실현 변동성 근사)으로 돌아가게 되어 있다.

가장 먼저 코드를 점검했다. 인증 헤더를 보내는 방식은 공식 문서와 일치했다. 코드 결함이 아니었다.

원인은 계정 쪽에 있었다. KRX Open API는 인증키 발급과 API 서비스별 이용신청이 별개 절차다. 키 자체는 유효했지만, VKOSPI가 들어 있는 “파생상품지수 시세정보” 서비스에 대한 개별 이용신청이 안 된 상태였다. 포털의 이용현황 화면에 해당 서비스가 아예 없었다. 신청하자 바로 승인됐고, 다음 매수 사이클부터 실측값이 정상적으로 들어오는 것을 확인했다.

구분 확인
승인 이전 사이클 대체값(실현 변동성 근사) 사용
승인 이후 사이클 KRX 실측 종가로 전환, 값이 정상 범위(0~100)
코드 변경 없음

교훈: 401은 “키가 틀렸다"가 아니라 “이 서비스를 쓸 권한이 없다"일 수도 있다. 외부 API 오류는 코드보다 계정·권한 단계를 먼저 확인하는 쪽이 빠르다.

2. “매수 금액이 너무 적다” — 버그가 아니라 방어 로직이었다#

같은 날 “손절이 자주 나오고, 매수 금액이 보유 현금에 비해 적어 보인다. 매수량을 올려야 하지 않나"라는 제보가 들어왔다. 당일 로그와 DB 복사본으로 조사했다.

  • 시장 컨텍스트 로그를 보니 종일 공포 단계가 가장 높은 구간이었고, 코스피가 중기 이동평균선 아래에 있었다.
  • 두 조건이 겹치면 포지션 배율이 시스템 최저 하한까지 내려간다. 종목당 매수 예산은 “총 평가금액 × 안전 비율 ÷ 종목 수 × 배율"로 계산되는데, 로그에 찍힌 매수 예산이 이 식의 결과와 정확히 일치했다.
  • KRX 원본 응답도 직접 호출해 확인했다. 지수 행이 날짜당 하나뿐이라 파싱 모호성이 없었고, 실측값이 로그 값과 같았다. 오전의 401 구간에는 대체값을, 이후에는 더 높은 실측값을 썼다. “버그로 낮아진 값"이 아니라 실제로 시장이 극단적 수치를 보고 있었다.

그래서 매수량을 강제로 올리지 않았다. 올리면 실측 데이터에 기반한 방어 동작을 무력화하는 셈이다. 손절이 평소보다 잦았던 점도 시장 하락 국면과 방향이 일치해 정상 반응으로 판단했고, 손절 후 재진입 쿨다운 정책은 데이터가 더 쌓인 뒤 논의하기로 보류했다.

교훈: 제보를 곧바로 코드 수정으로 연결하지 않는다. 먼저 “지금 동작이 설계대로인가"를 로그 수치로 검산하면, 안전장치를 실수로 풀어 버리는 사고를 막을 수 있다.

3. 조사 중 찾은 진짜 버그 — 미완성 봉이 이동평균에 섞였다#

조사하다가 로그의 “시장 위치 판정” 이동평균 값이 15분 사이클마다 미세하게 흔들리는 것을 발견했다. 원인은 classify_market_position()이 지수 일봉 목록의 첫 번째 항목(당일 미완성 봉)까지 포함해 20·60·200일 이동평균을 계산한 것이었다. 프로젝트 규칙은 “지표는 완성된 봉 기준으로 계산한다"인데 이 함수만 어겼다.

수정은 첫 항목을 제외하는 한 줄이었다. 중요한 건 순서였다.

  1. 첫 항목을 극단값으로 바꾼 회귀 테스트를 먼저 작성해 실패하는 것을 확인(RED)
  2. 수정 후 통과(GREEN), 전체 테스트 통과 확인

같은 패턴이 비활성 전략(v1)의 파일에도 있었지만, “v1 내부 파일은 수정하지 않는다"는 원칙과 v1이 운영에서 꺼져 있다는 점을 근거로 그대로 두었다.

정리#

제보 판정 조치
VKOSPI 401 오류 코드 결함 아님 — API 서비스 이용신청 누락 신청·승인, 코드 변경 없음
매수 금액이 적다 버그 아님 — 공포 필터와 시장 위치에 따른 정상 방어 변경 없음, 증거 수치로 검산
이동평균이 흔들림 버그 — 미완성 봉이 계산에 포함 RED 테스트 후 수정
손절 빈발 시장 국면과 일치, 결함 못 찾음 재진입 쿨다운은 보류

배운 점: 같은 “이상하다"라는 제보라도 설정 문제, 정상 동작, 진짜 버그가 섞여 있다. 원인을 가른 뒤에야 고칠지 말지가 정해진다.
