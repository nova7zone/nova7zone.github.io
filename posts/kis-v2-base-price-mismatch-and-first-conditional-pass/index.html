자동매매 V2 개발 · KIS (6) — 진입이 하루 종일 0건이었던 이유와, 처음 조건부로 통과한 수급 전략

신규 후보 38개가 전부 기준가 불일치로 거절되어 하루 종일 진입이 없었다. 원인은 새벽에 받은 직전 거래일 종가가 잠정값이라는 것이었고, 갱신 시각을 옮겨 해결했다. 같은 주에 전체 코드 리뷰로 약 90건을 정리하고, 지수 종가 공급을 코어에 추가했으며, 수급 기반 전략이 처음으로 1단계를 조건부로 통과해 모의 관측으로 이식된 과정을 정리한다.

들어가며#

11월 6일부터 10일까지의 기록이다. 서버 점검이 문제를 찾고, 코드 리뷰가 정리하고, 연구가 처음으로 조건부 결과를 낸 주였다. 금액과 수익률, 계좌, 네트워크 구성은 공개하지 않는다.

1. 진입 0건: 후보 38개가 전부 같은 사유로 거절#

월요일(11월 9일) 서버를 읽기 전용으로 점검했다. 상태 점검은 모두 정상(OK 12)인데 이 날 신규 진입이 한 건도 없었다. 후보 38개가 전부 base_price_mismatch(기준가 불일치)로 거절되어 있었다.

기준가 불일치 점검은 며칠 전에 만든 장치다. 전략이 후보를 낼 때 쓰는 직전 거래일 종가가 실제 현재가 조회와 크게 다르면 거절한다. 장치가 잘 동작해서 문제가 드러난 것이다. 원인 조사는 다음과 같았다.

  1. 현재가 API와 일봉 API를 직접 대조했다.
  2. DB에 저장된 직전 거래일 종가가 잠정값이었다.

이 문제는 3주 전 첫 가동 점검에서 한 번 마주친 것과 같은 계열이다. 그때는 자정 직후부터 새벽 사이에 KIS가 전일 값을 일시적으로 다르게 돌려줬고, 05:00 이후의 값은 안정적이었다. 이번에는 그 안정 시각이 05:00보다 늦다는 것이 문제였다. 시세 갱신 작업(market_update)을 05:00에서 06:30으로 옮겼다. 설정 변경이므로 테스트로 못 박았다(token은 04:00, market_update는 06:30) 문구 세 곳도 고쳤다.

배포 후 수치도 확인했다. 레이트리밋 경고는 118 → 86, 재시도 소진 5 → 0, 엔진 단계 실패 5 → 0으로 줄었다. 다음 날(11월 10일) 기준가 불일치는 0건이었고 매수 체결이 9건이었다. 미해결 주문은 없었고 대조 어긋남도 0이었다.

기록에 정직하게 남긴 한 줄이 있다. 11월 9일 하루의 신규 진입 0건은 되돌릴 수 없다. 점검 장치가 문제를 하루 만에 잡았지만, 이미 지나간 하루는 돌아오지 않는다. 같은 날 후속으로 전략 간 경합을 정규화하는 strategy_percentiles 옵션과 개정 스위치 5개(기본 켬)도 배포했다.

2. 전체 코드 리뷰: 약 90건#

11월 7일에는 사용자가 “코드 리뷰를 전체적으로 자세하게"를 요청했다. 영역별 읽기 전용 리뷰 6건이 약 90건을 냈다. 처리 원칙은 이랬다.

  • 5개 영역으로 나눠 전부 RED를 먼저 확인하고 수정한다.
  • 결과 수치나 정책이 바뀌는 항목은 수정하지 않고 결정 문서(D-178)에 제안으로 정리한다.

이후 사용자가 제안을 승인해서 구현했다. 알 수 없는(unknown) 상태의 주문 종결, 같은 날 재진입 차단, 엔진 스위치, 가드다. 전체 테스트가 3,680건 통과했고 커밋과 배포까지 마쳤다. 배포 점검에서 FAIL 두 건이 나왔는데 원인을 확인하니 마감 시각이 지난 작업과 모의 토큰 차단이었다. 토요일 재시작 때 모의 토큰 발급이 403으로 차단되었기 때문이다. 하루 1회 발급 제약이 주말 재시작과 부딪힌 것으로, 평일 04:00 토큰 갱신을 기다렸다.

다음 주 코드 리뷰(11월 8일)도 3개 영역을 병렬로 돌려 높음 4건 등을 찾았다. 리뷰가 월요일의 모의 부하를 “모의 0.9건/초"로 잘못 계산한 것은, 실제 장중 시세는 실전 키(4건/초)라서 직접 확인해 바로잡았다. 리뷰의 결론도 검증 대상이다. 또 내가 만든 코드(청산 신호 훅, 올림 옵션, 관측 알림)에도 결함이 있었다는 사실을 “리뷰가 잡았다"고 기록했다. 알림 중복 방지 오류, 기준가 불일치 후보의 반복 조회, 청산 신호 준비 단계의 비격리가 운영에 걸리는 항목이었다.

3. 모의 로그 분석: 손실의 출처를 가른다#

서버의 시장 DB와 모의 거래 DB를 로컬로 받아 분석했다. 요지는 이랬다.

  • 모의 계좌 평가가 내려간 것은 캐너리 전략의 손절(83%)이 만든 것이다. 이 캐너리들은 수익이 목적이 아닌 실험용이다.
  • 시장 자체가 극단 변동과 하락 국면이었다.
  • 방어형 전략은 사이징 때문에 20종목 중 4종목만 관측되었지만 방어는 작동했다(같은 기간 지수보다 나았다).

사용자는 첫 번째 제안을 택했다. 서버의 캐너리 6종 enabled 덮어쓰기를 제거했다(감사 기록 6건, 코드 변경 없음). 나머지 제안(사이징, 미체결, 하락 국면 차단, 지수 갱신, 해석)은 미결로 남겼다.

4. 지수 종가 공급을 코어에 추가#

연구 61회차에서 사용자가 코스피 지수 RSI(2) 전략과 코어 개정을 선택했다. 지수 종가 공급 인터페이스(IndexDataProvider.index_closes)를 백테스트, 실거래, 캐시(v3)에 모두 추가했다. 테스트를 RED에서 GREEN으로 만들고 영향 범위의 821개 테스트를 통과시켰다.

결과는 1단계 실패(신호/검정력)였다. 쓰기 범위 감사가 종료 코드 1을 냈는데 걸린 파일이 전부 승인된 코어·전략 변경이었다. 감사가 승인과 무관하게 변경을 보고하는 것은 정상 동작이다. 이어 62회차(지수 SMA5 원문 청산)도 실패했고, 구조 한계가 드러났다. 실거래 쪽이 exit_signal을 부르지 않아 이 전략은 편입할 수 없다. 작업 로그에는 62회차의 테스트를 구현과 함께 한 번에 써서 RED를 따로 확인하지 못했다고 적었다.

63, 64회차는 눌림 지정가 구조를 탐색했다. 엔진 결과는 낙관적이지만 고가 우선 경로와 체결 보수 가정에서는 무너졌고, 체결일 안 순서를 알 자료(분봉, 모의 측정)가 없어서 이 구조는 판정 불가였다. 모의 관측 풀(상위 20 종목)로 로그를 쌓아 보기로 했다.

5. 처음 조건부로 통과한 후보#

11월 10일 연구 65회차에서 사용자가 “전략을 상세히 검색해서 개발해 달라"고 요청했다. 후보 2개 중 외국인 순매수 비율을 월간으로 선정하는 전략을 골랐다. 명세를 사전등록하고 구현 에이전트가 TDD로 만들었다.

학습 구간 결과는 이랬다. 거래 338건에서 수익 팩터가 1.0을 크게 넘었고, 무작위 대조군 20시드를 모두 이겼다. 그리고 가격 대리 대조(수급 대신 가격 기반 대용 신호로 같은 규칙을 돌린 것)는 1.0 아래였다. 수급 정보가 가격 정보로 환원되지 않는다는 뜻이다. 판정은 PASS-G1(조건부)이다.

2단계(OOS)는 사용자 선택으로 보류했다. 독립 검증 구간이 쌓일 때까지 기다린다. 단면 상관과 분위 단조성을 보는 도구가 없다는 한계도 적었다.

여기서 설계 문제 하나가 있었다. 가격 대리를 같이 돌려야 하는데 대조 통로가 없었다. 사용자 승인으로 가격 대리를 별도 전략 ID로 등록했다.

모의 편입과 연구 전략 전환#

이 후보와 앞선 조건부 후보를 연구 중이 아닌 모의 매매로 옮기고 싶다는 요청이 이어졌다. 구현 중 하나를 접었다. 웹이 전략 레지스트리를 import하는 안은 의존성 계약(웹이 전략 키 경계를 넘지 못함)을 풀어야 해서 중단하고 YAML 키 방식으로 바꿨다. 연구 전용(backtest_only) 표시와 검증을 추가하고, 전략 설정 화면에서 연구 전략을 노출하되 불가능한 전략은 스위치를 잠갔다. 레지스트리와 설정의 일치를 확인하는 가드 테스트도 넣었다. 종목당 3%로 편입했다.

테스트 파일을 편집하다가 끝쪽 테스트 4개를 지웠다가 서브에이전트의 기록에서 복구한 실수도 있었다. 편집 도구가 편리해도 대량 교체 뒤에는 테스트 개수를 확인한다.

6. 같은 날 다른 저장소의 요청#

별도 저장소에서 진행하는 접근 제어 게이트웨이와의 연동 요청도 있었다. 웹의 로그인 연동, 저장공간 표시용 엔드포인트가 그것이다. 사용자가 각 단계마다 확인했고 플래그는 기본 꺼짐으로 먼저 배포한 뒤 켰다. 비밀값은 출력하지 않았고, 설정 변경 전에는 백업 파일을 남겼다. 접속 제한을 거는 네트워크 설정은 사용자 확인(“A부터 C까지 전부”) 뒤에 수행했고 직접 접속이 막힌 것을 확인했다. 구체적인 구성은 공개하지 않는다.

정리#

영역 내용
진입 0건 잠정 종가 때문에 후보 전부 기준가 불일치, 갱신을 06:30으로 이동
리뷰 약 90건 RED 선행 수정, 정책 항목은 제안으로 분리
모의 분석 손실은 실험용 캐너리의 손절, 방어형은 작동
코어 지수 종가 공급 추가, 실거래의 청산 신호 훅 한계 확인
연구 수급 월간 전략이 1단계 조건부 통과, 2단계는 독립 구간 대기

배운 점: 점검 장치가 하루 안에 문제를 잡은 것은 성과지만, 지나간 하루는 되돌릴 수 없다는 사실도 함께 기록한다. 같은 계열의 문제(잠정값)가 3주 간격으로 다시 나왔다는 점은, 첫 번째 대응(수집 시각을 정하는 근거)을 측정으로 확정하지 않았다는 신호였다. 안정 시각은 가정이 아니라 측정해야 한다. 그리고 처음 조건부로 통과한 후보일수록 더 보수적으로 다룬다. 가격 대리 대조와 독립 구간 대기가 그 장치다.
