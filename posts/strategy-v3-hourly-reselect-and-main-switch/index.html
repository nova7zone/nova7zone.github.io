자동매매 코드 개발 (42) — strategy_v3 매시간 재선정, 메인 전략 v3 전환

v3에 09시 1회 선정 대신 매시간 재선정 기능을 추가하고, 지난 세션 외부 리뷰 문서의 배선 가드·관찰성 로그·거래량 정규화 보강까지 마친 뒤, 메인 전략을 v1에서 v3/aggressive로 전환한 하루를 정리한다.

들어가며#

이전 글에서 config_loader 이중 중첩 버그를 잡아 strategy_sell.yaml 설정값이 실제로 반영되게 만들었다. 7월 2일은 v3의 마지막 핵심 기능인 매시간 재선정을 구현하고, 외부 리뷰 문서의 후속 보강을 마친 뒤, 드디어 메인 전략을 v3로 전환하는 날이다.

결론부터 말하면, 기존 09:00 1회 선정 방식에 매시간(09~14시) 재선정 옵션을 추가했다. 이어서 지난 세션 외부 리뷰가 지적한 배선(wiring) 가드·관찰성 로그·거래량 정규화 3가지를 보강했다. 마지막으로 active_strategy_version을 v1에서 v3로, 프리셋을 neutral에서 aggressive로 전환했다.

매시간 재선정 구현 (Task 1~6)#

작업 요청서와 계획 문서를 기반으로 subagent-driven-development로 Task 1~6을 전부 구현했다. 선행 조건(post-review-hardening Rev.2)은 이미 병합 완료 상태에서 시작했다.

Task 1 — run_state 스키마 확장 + 시간창 + 시간대별 스냅샷: first_stage_groups.py의 run_state가 불리언 candidates_selected에서 정수 last_selection_hour로 확장됐다(_last_selection_hour() 3단 우선순위 — 신규 키 → 구 불리언(True→9) → None). mark_candidates_selected(hour) 시그니처가 변경됐고(hour 필수), is_selection_window(now, reselect_cfg)는 비활성/None 시 기존 09:00-09:59 그대로, 활성 시 09:00~end_hour로 확장됐다. should_reselect(), save_candidate_pool_snapshot()도 신규 추가됐다. can_generate_pool()은 변경 없음(리뷰어가 byte-identical 확인).

Task 2 — reselect.yaml 전용 설정 파일: strategy_v3/settings/screen_config/reselect.yaml 신규(enabled: true, interval_hours: 1, end_hour: 15). config_loader.py::_load_screening_configs_v3()가 config["reselect"]로 로드하고, 파일 없으면 {} 기본값을 쓴다.

Task 3 — buy.py 배선: run_buy()의 후보 풀 준비 블록을 should_reselect/is_selection_window/mark_candidates_selected(hour)/save_candidate_pool_snapshot 기반으로 전면 교체했다. reselect.enabled=true 시 can_generate_pool()(13:00 컷오프)을 우회한다.

구현 중 부수 발견이 있었다 — 계획 문서의 테스트 코드를 그대로 쓰면 실제 운영 중인 data/cache 상태(gitignore 대상)와 충돌해 클린 CI 체크아웃에서 깨지는 테스트 격리 버그가 있었다. monkeypatch.chdir(tmp_path) + cache_dir 경로 보정, 기존 테스트 3개의 should_reselect patch 추가로 수정했다(buy.py 프로덕션 코드는 계획 문서 그대로, 테스트 파일에만 격리를 보강했다).

Task 4 — 메인 전략 v3/aggressive 전환: settings/app.yaml의 active_strategy_version: "v1" → "v3", active_preset: neutral → aggressive로 변경했다. aggressive 프리셋을 검토한 결과, v3 trading 설정(max_holding_count=20 등)은 v2와 완전히 동일했다. 프로파일별 min_score는 v3(momentum/trend_following/balanced/reversal/fear_driven = 47/47/47/37/52)가 v2(55/55/50/45/60)보다 낮지만, 그룹 정규화 점수 체계(0~100 스케일) 자체가 v2 원점수 체계와 달라서 상대적으로 비슷한 완화 수준이었다 — 조정 불필요로 결론지었다.

Task 5 — 문서화: PLAN_03_TRADING.md에 “8-5. 매시간 재선정” 섹션, PLAN_02_SCREENING.md에 “매시간 재선정 설정” 섹션을 추가했다.

Task 6 — 완료 기준 재확인: §1-4 screening_log 결론 — screening_log 테이블에 log_date UNIQUE 제약이 없고 created_at이 자동으로 매 행의 시각을 기록하며 get_screening_logs()가 이미 created_at DESC로 정렬하고 있어서, 스키마/포맷 변경 없이 재선정마다 그대로 insert_screening_log()를 호출하면 됐다. 요청서 완료 기준 6개 체크박스 중 4개는 Task 1·3의 단위·통합 테스트로 커버 확인했고, 나머지 2개(Group A/B 종목명 실로그, API 예산 잔여)는 코드로 검증 불가해 next-tasks.md로 이월했다.

pytest tests/ -q → 887 passed, 163 warnings(0 failed), 소요 약 123초.

외부 리뷰 후속 보강 3건#

지난 세션 외부 리뷰 문서(2026-07-02-v3-post-review-hardening.md)의 3개 섹션을 subagent-driven-development로 전부 구현했다.

§1 배선 가드 — Critical 버그(2b189e1) 재발 방지: second_stage.py::run_second_stage()에서, condition_groups가 비어 있으면 조용히 0점 처리하던 것을 [V3_WIRING] 에러 로그 + 즉시 반환(일봉 조회 스킵)으로 바꿨다. buy.py의 group_configs 조립 로직도 인라인 블록에서 _build_group_configs() 실함수로 추출했다 — 기존 회귀 테스트가 테스트 파일 안의 손 복사본이라 실제 코드 변경을 못 따라가는 사각지대가 있었는데, 신규 테스트가 실함수를 직접 import해 호출하도록 바꿨다.

§3-1 관찰성 로그: first_stage_groups.py::_score_group()에 그룹별 “1차 퍼널 | 그룹=%s | 1차선정=%d | 가격필터탈락=%d | 2차대상=%d” 로그를 추가했다. 1차 선정 0건(예: Group D)도 반드시 기록한다.

§3-2 Group A/D 거래량 비율 정규화: 개장 직후 당일 누적거래량이 일평균의 극히 일부라 raw ratio가 구조적으로 낮게 측정되던 문제가 있었다(cron.log 실측 — Group D가 지금까지 후보를 낸 적이 없었다). 경과 시간 대비 기대 비율로 정규화하는 _expected_volume_ratio_now()를 추가했다(09:05·5% 체결 → 보정 후 ≈3.9배). v2/v3 동시 반영했다. v2 적용 중 부수 발견도 있었다 — 기존 테스트가 now_kst()를 patch하지 않아 실행 시각(14:00 KST 이전)에 따라 flaky해지는 문제를 발견해, 보정 영향이 없는 15:30(경과 390분, 보정계수 1.0) 시점으로 고정했다. 이는 같은 세션 앞부분에서 발견한 UTC/KST 자정 경계 date rot과 같은 계열의 “wall-clock 미고정 테스트” 버그였다.

§2 매수 사이징 총량 배분: run_buy() 종료 시 “총매수금액=X원 | 목표배분=Y원 | 편차=Z%” 로그를 추가했다. 실측 없이 사이클 단위 강제 가드부터 만드는 과설계를 피하고, 관찰부터 시작해 실제 편차를 본 뒤 필요 여부를 판단하는 순서를 따랐다. 정렬기준도 확인했는데, run_full_screening()은 그룹 우선순위가 아니라 점수 내림차순으로 병합·정렬한다 — _calc_size_multiplier()의 1.2배 혜택은 그룹과 무관하게 “그 사이클에서 점수가 가장 높은 종목부터” 돌아간다는 뜻이다.

세션 진행 중 발견한 별도 이슈도 하나 있었다 — 지난 세션(오전)에서 만든 Group A/B/D 종목명 빈 문자열 버그 수정(v2+v3)이 커밋되지 않은 채 작업 디렉터리에 남아 있었고, subagent가 같은 파일을 공유 작업 디렉터리에서 편집하면서 이후 커밋들에 의도치 않게 섞여 들어갔다. task reviewer가 “scope violation"으로 정확히 잡아내서, git reset --soft + 선택적 재커밋으로 히스토리를 분리해 독립 커밋으로 정리했다.
