AI를 이용한 자동매매 프로그램 작성 (40) — strategy_v3 구현 완료, 매수 전면 중단 Critical 버그

그룹 정규화 스크리닝 방식의 새 전략 엔진 strategy_v3의 남은 Task 9~12를 완료하고, 최종 whole-branch 리뷰에서 실거래 시 모든 후보 종목이 0점 처리돼 매수가 전혀 발생하지 않았을 Critical 버그를 발견·수정한 과정을 정리한다.

들어가며#

이전 글에서 텔레그램 알림 버그와 손실 매도 버그를 고치고 v0.6.4를 릴리즈했다. 7월 1일부터는 그동안 v1/v2와는 별개로 준비해오던 세 번째 전략 엔진, strategy_v3의 마무리 작업으로 넘어간다.

결론부터 말하면, 이전 세션에서 Task 18까지 진행하다 중단됐던 strategy_v3 구현을 이어서 Task 912까지 완료했다. 그런데 전체 브랜치를 한 번에 보는 최종 리뷰에서, 실거래에 배포됐다면 매수가 전혀 발생하지 않았을 Critical 버그를 발견했다.

strategy_v3란#

v1은 조건별 가중치 합산 방식, v2는 4개 그룹(A/B/C/D) 통합 선정 + 풀링 매수 방식이었다. v3는 여기서 한 걸음 더 나아가 그룹 정규화 스크리닝 방식을 쓴다 — 여러 그룹(G1G5)의 점수를 각각 0100 스케일로 정규화한 뒤 합산하고, 5개 프로파일(momentum/trend_following/balanced/reversal/fear_driven)마다 서로 다른 최소 점수(min_score)와 목표가 계산 방식(즉시/할인/기술적)을 적용한다. 매수 후에는 시간이 지날수록 손절/기회비용 기준으로 청산하는 보유기간 관리 로직도 갖췄다.

이번 세션에서 이어서 완료한 Task 9~12는 다음과 같다.

  • Task 9: utils/config_loader.py에 _load_screening_configs_v3() 추가 — condition_groups 구조(v2의 condition_weights와 다름)를 로드하고, v3 전용 strategy_sell/daily_reeval YAML과 v2 공유 운영 YAML을 조합
  • Task 10: utils/reconcile.py(strategy_version in ("v2", "v3") 분기), strategy_v2/daily_reeval.py(_call_score() 버전 분기 wrapper — v3는 3-tuple, v2는 2-tuple 언패킹)
  • Task 11: runner.py v3 elif 분기 + _has_legacy_v2_holdings()(v3 활성 중 v2 잔존 포지션 병행 매도) + --pre-market/--next-pre-market v3 허용, web/routers/config_router.py의 get_screening_strategy() v3 condition_groups 지원. 구현 중 실제 버그 하나를 발견했다 — v3 프로파일 선택자 파일 strategy_v3/settings/screen_config/second_stage.yaml이 아예 없어서 config_router가 FileNotFoundError를 낼 뻔한 것을 확인해 생성
  • Task 12: tests/test_v3_integration.py 통합 스모크 테스트 3건 추가(_score_stock end-to-end, calculate_target_price end-to-end, db/schema.py v3 컬럼 5개 생성 확인)

각 Task는 subagent 구현 → task-reviewer 검토(spec 준수 + 코드 품질) → Important 발견 시 fix subagent → 재검토 순으로 진행했다. Task 9(모킹만 하던 테스트를 실제 동작 검증으로 교체)·Task 10(v3-routing과 v1-fallback을 구분 못 하던 테스트 강화)에서 각 1회 재검토 루프가 발생했지만 모두 clean 통과했다.

최종 리뷰가 잡은 Critical 버그#

Task별 리뷰는 전부 통과했다. 하지만 전체 변경사항(범위 a002495..5b648ed)을 한 번에 보는 최종 whole-branch 리뷰(opus 모델)에서 Critical 버그 1건이 나왔다.

strategy_v3/trading/buy.py가 2차 스크리닝용 group_configs에 profile_config(전체 YAML, condition_groups 포함) 키를 누락하고 있었다. 이 때문에 first_stage_groups.run_full_screening()이 빈 condition_groups로 폴백해서 모든 후보 종목이 0점 처리되는 상태였다 — v3를 활성화해서 실거래에 배포했다면 매수가 전혀 발생하지 않았을 버그다.

문제는 어떤 개별 Task 리뷰도 이 흐름을 잡아내지 못했다는 점이다. Task 5 리뷰는 buy.py만 봤고, Task 2 리뷰는 second_stage.py만 봤다 — 각 파일은 자기 안에서 논리적으로 맞았지만, 두 파일 사이의 연결(배선)이 끊어져 있었다.

Important 2건도 함께 발견됐다.

  • candidate["profile_name"]이 어디서도 설정되지 않아 entry_profile이 항상 NULL로 저장되고, _calc_size_multiplier()가 항상 balanced 분기로 폴백(프로파일별 차등 사이징이 작동하지 않음). 매도 시 _load_profile_for_sell()도 항상 balanced.yaml로 폴백
  • daily_reeval.py가 active_strategy_version=v3 전환 후에도 잔존하는 managed_by='v2' 포지션을 v3 점수 기준으로 재평가하던 버그

수정 커밋(2b189e1)으로 3건 모두 해결하고 회귀 테스트 6건을 추가했다(5건 RED→GREEN 확인, 1건은 중복이라 무해하다고 정직하게 명시). 재검토는 “Ready to merge: Yes"로 통과했다.

최종 상태#

pytest tests/ 841건 전체 통과를 확인했다. feature/build에 v3 관련 커밋 16개(f8bac12~2b189e1)가 적재됐다.

배포 후 확인이 필요한 항목도 명확히 남겨뒀다 — active_strategy_version=v3 전환 후 매수 체결 시 position_registry에 managed_by='v3', entry_profile(NULL 아님), entry_group_scores가 실제로 기록되는지가 핵심이다. 이번에 고친 Critical/Important 버그가 실거래에서도 해소됐는지의 직접적 검증이 되기 때문이다. strategy_v3/specs/PLAN_04_INFRA.md의 “Step 9 — 검증 계획” 체크리스트를 참고 문서로 남겨뒀다.

범위 밖으로 남긴 항목도 있다. test_target_price_technical_trend(MA20 분기)와 test_score_vs_v2_comparison 단위 테스트는 Task 12 브리프가 요청한 3건에 포함되지 않아 미작성 상태로 남았다.
