자동매매 코드 개발 (39) — 텔레그램 마크다운 파싱 버그, v0.6.4 릴리즈

들어가며#

이전 글에서 CLAUDE.md를 분리하고 v0.6.3을 릴리즈했다. 6월 30일은 텔레그램 알림이 실패하는 문제와, 6월 25일 고쳤던 손실 매도 버그가 다른 경로로 재발한 사고를 함께 처리했다.

결론부터 말하면, 전략명에 포함된 언더스코어를 이스케이프하지 않고 텔레그램 마크다운 메시지에 그대로 넣어 파싱 오류가 반복되고 있었다. 그리고 6월 25일에 고친 reversal/fear_driven 손실 매도 버그가, 이번엔 candles 슬라이싱 방식 때문에 다른 경로로 재발했다 — 실제로 광주신세계에서 소폭 손실 매도 사고로 재현됐다. 두 수정을 묶어 PR #77을 머지하고 v0.6.4를 릴리즈했다.

텔레그램 마크다운 파싱 400 오류#

logs/cron.log 분석 결과, report/telegram_sender.py가 parse_mode="Markdown"(레거시 V1)으로 고정 전송하고 있었다. 그런데 strategy_v2/trading/buy.py의 매수 주문 접수 알림에서 target_strategy 값(trend_following/fear_driven 등 언더스코어 포함 전략명)을 이스케이프 없이 그대로 삽입해 “can’t parse entities” 400 오류가 반복 발생했다(2026-06-26, 06-30 등).

수정: report/telegram_sender.py에 escape_markdown() 헬퍼를 추가(_/*/`/[ 이스케이프)해서, buy.py의 target_strategy 보간부와 sell.py의 _REASON_MESSAGES.get(reason, reason) fallback(같은 버그 유형 방어)에 적용했다. daily_report.py/monthly_report.py의 의도된 굵게 표시(*텍스트*)는 영향받지 않도록 전역 제거 대신 호출부에서만 선별 적용했다.

fix: 텔레그램 매수/매도 알림 Markdown 파싱 400 오류 수정

TDD로 진행했다. tests/test_telegram_sender.py를 신규 작성(헬퍼 단위 테스트)하고, tests/test_v2_trading.py에 run_buy() 전체 흐름에서 notify 메시지 이스케이프를 검증하는 회귀 테스트를 추가해 수정 전 RED, 수정 후 GREEN을 확인했다. pytest tests/ 796개 전체 통과했다.

부가로, nohup.out, report/daily/가 .gitignore에 누락되어 있던 것을 OCI git status 점검 중 발견해 추가했다.

OCI 측 별도 조치(코드 변경 없음, 사용자가 PuTTY로 직접 실행)도 있었다. logs/update.log 분석으로 발견한 update_oci.sh의 미해결 git stash pop 충돌(strategy_v2/settings/screen_config/second_stage/reversal.yaml, 6/29 19:00:42 auto-stash)을 해결했다. 충돌 내용은 실제 파라미터 값 차이가 아니라 전부 포맷 차이(주석 유무, 45 vs 45.0, 따옴표 스타일)였다 — 웹 대시보드 YAML 저장 로직이 재직렬화 시 주석을 지우는 것이 원인으로 추정된다. git checkout --theirs + git add + stash@{0} drop으로 해결했고 값 손실은 없었다.

reversal/fear_driven 손실 매도 버그, 다른 경로로 재발#

6월 25일 고쳤던 VWAP 목표가 버그와는 다른 각도의 문제가 다시 나타났다. _check_strategy_trigger()가 eval_candles = candles[1:]로 슬라이스한 뒤 reversal/fear_driven 서브함수에 eval_candles를 전달하면, 서브함수 내 candles[0]은 원본 candles[1](어제 종가)이 된다. PR #70의 profit_pct > 0 가드는 이 어제 종가와 비교하기 때문에, “어제는 수익, 오늘은 손실” 상황에서도 target_reached가 발동할 수 있었다.

2026-06-30 09:15 특정 종목 소폭 손실 매도 사고로 재현됐다.

수정: _check_strategy_trigger()에서 슬라이스 전에 candles[0]["stck_clpr"]를 today_price로 추출해 reversal/fear_driven 서브함수에 전달하고, 서브함수는 이 값을 current_price로 사용하도록 바꿨다.

fix(strategy_sell): reversal/fear_driven 수익률 비교 기준을 어제 종가→오늘 실시간 가격으로 교정

회귀 테스트 2건(candles[0] < entry_price < candles[1] 시나리오)을 추가했다. pytest 21/21 통과를 확인했다.

로그 리뷰(6/29 18:00 ~ 6/30 09:15)도 함께 진행했다.

  • LOG_LEVEL=DEBUG 수정 반영 확인: cron_next_pre.log에 urllib3/filelock/token_manager DEBUG 로그 정상 출력
  • cache_manager 버그 수정 반영 확인: 6/30 09:00 “시장 국면 감지: 캐시 사용 | 건수=233” — 그룹 A/C/D 캐시 정상 동작
  • qty_before 3-state 처리: 해당 기간 취소/좀비 주문 관련 로그 없음(검증 기회 아직 없음)
  • Paper API 500 오류: 계속 “시도=1/3"에서 재시도 성공, 최대 재시도 초과 없음
  • 텔레그램 400 오류: 6/30 09:01:53 “Bad Request” 1건(원인 미조사, 2순위)

PR #77 머지 + v0.6.4 릴리즈#

PR #77(텔레그램 마크다운 파싱 오류 수정 + reversal/fear_driven 재수정 + 투자원금 ledger 전환 + extra-accounts 캐시 버그 수정 + .gitignore 보강)의 CI(test) SUCCESS를 확인한 뒤 --squash로 master에 머지(머지 커밋 76d6d60)했다. git fetch origin master && git merge origin/master로 feature/build를 동기화했고, 충돌 없이 완료 후 push했다.

v0.6.4 태그를 master HEAD(76d6d60)에 생성·push하고, release-notes-draft-v0.6.4.md 내용으로 GitHub Release를 게시했다.

OCI 측 별도 조치도 있었다. update_oci.sh의 미해결 git stash pop 충돌(reversal.yaml, 6/29 19:00:42 auto-stash)을 사용자가 PuTTY로 직접 해결했다 — 실제 파라미터 값 차이는 없었고 전부 포맷 차이(주석 유무 등)였다.
