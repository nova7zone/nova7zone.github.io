자동매매 V2 개발 · KIS (4) — 한 번에 조건 하나씩: 사전등록 프로그램과 대조군 20시드로 연구하기

국내 주식 전략 연구 회차 27번가량을 사흘 동안 돌린 기록. 후보를 하나씩 평가하는 대신 가장 단순한 기준선에서 조건을 하나씩 더하는 '프로그램' 방식으로 바꾸고, 같은 규칙의 무작위 대조군 20시드와 비교해 채택 여부를 정했다. 도구 버그, 구조 결함 조기 발견, 국면 사이징을 전략별 설정으로 옮긴 설계와 처음 조건부로 살아남은 후보까지 정리한다.

들어가며#

10월 27일부터 29일 사이에 연구 회차 6번부터 37번까지를 돌렸다. 대부분은 1단계 게이트(G1)에서 끝났다. 전략의 규칙과 지표별 수치는 공개하지 않고, 이 기간에 굳어진 방법과 도구·설계 쪽 교훈만 정리한다.

1. 국면 사이징을 먼저 사전등록으로 검토했다#

사용자가 국면에 따라 포지션 크기를 조정하는 장치(국면 사이징)의 필요성을 물었다. 기존 전략 전체에 대해 protocol.md를 결과를 열람하기 전에 사전등록하고 54회를 돌렸다(약 35분).

결과 집계에서 오류가 하나 있었다. 집계 스크립트가 사이징 행의 수익 팩터·낙폭 열을 잘못 읽어(열 위치) “해롭다 6/6"이라는 반대 결과가 나왔다. 파서만 고치고 규칙은 그대로 둔 채 다시 집계했다. 결과는 규칙상 “도움 6/6"이었지만, 대부분은 단순한 노출 감소 효과였다(사후 분석). 유니버스 제한은 개선이 0건이었다. 그래서 공용 설정으로 켜지 않고 사용자 결정으로 남겼다.

이어서 구조를 바꿨다. 전역 국면 사이징 스위치를 폐지하고, 전략별 EntryPolicy(사이징, 차단할 국면, 최대 보유 수)로 설정에서 대시보드, 런타임, 진입 게이트, 백테스트 엔진까지 연결했다. 옛 덮어쓰기는 폐기 키 목록으로 무시한다. 사용자가 이렇게 말했다. “전략별 국면 차단을 하면 글로벌에서 빠져야 하겠지?” 맞는 말이다. 같은 일을 하는 설정이 두 곳에 있으면 서로 모순될 수 있다.

구현 중에 테스트가 잡은 함정이 있었다. 국면 사이징에 참여하지 않는 전략에 국면을 None으로 주면 “국면을 모르면 최소 계수” 규칙 때문에 오히려 비중이 줄어들었다. 값을 비우는 대신 설정 자체를 끄는 방식으로 고쳤다.

2. 후보 하나씩 vs. 프로그램#

6회차부터 15회차 안팎까지는 후보마다 독립 회차로 평가했다. 대부분이 신호 대비 비용이나 무작위 대조군에 지는 형태로 FAIL-G1이었다. 그런 상황에서 사용자가 새로운 방식을 제안했다. “가장 단순한 조건의 전략에서 조건을 바꿔 가며 수정해 보자.”

단순 기준선 프로그램#

  • 프로그램 문서에 규칙을 사전등록한다. 개정은 이력으로 남긴다.
  • 기준선 B0는 선정 조건 없이 매수하는 가장 단순한 전략이다.
  • 후보 조건 6개를 권고 순서(진입 필터 4, 청산 2)로 한 번에 하나씩 추가해서 시험한다.
  • 각 단계마다 시드 0 장부(상세 거래 기록) 3칸과, 같은 규칙으로 무작위로 뽑은 대조군 20시드의 분포를 비교한다. 차이가 사전등록된 문턱을 넘고 인접 칸도 통과하면 채택(STEP-ADOPT), 아니면 폐기(STEP-DISCARD)다.

결과는 6단계 중 1단계(상위 극단값 종목 제외)만 채택되었다. 나머지 다섯은 모두 문턱 미달로 폐기되었다. 최종 구성은 기준선 대비 성과가 개선되었지만 수익 팩터 중앙값이 1.0 미만이어서 프로그램은 FAIL-G1로 끝났다. 검증(OOS) 구간은 열람하지 않았다.

이 방식이 드러낸 문제들#

  • 구조 결함의 조기 발견. 처음 기준선(거래대금 순 선정)은 거부 사유 already_holding이 85%였다. 매일 같은 종목을 뽑아서 이미 보유 중이라 거절되었다. 규칙을 바꾸기 전에 구조적 결함으로 판단해, 풀 안에서 무작위로 뽑는 정의로 바꿨다. 첫 검사 결과를 보고 기준선 정의를 바꾼 점은 숨기지 않고 “구조 근거"로 기록했다.
  • 도구 버그. 대조군 20시드를 --workers 하위 프로세스로 돌릴 때 --risk 옵션이 전달되지 않았다. 발견해서 고치고 다시 측정했다. 이전에 돌린 search --workers 4가 같은 DB의 첫 캐시를 동시에 만들려다 충돌한 일도 있었다. 첫 적재 명령은 하나씩 돌린다.
  • 반올림이 판정을 흐린다. 대조군의 중앙값이 반올림 값뿐이어서 문턱 경계 판정이 모호했다. 도구에 시드별 원자료 JSON 출력을 추가하고 다시 돌렸다.
  • 공정한 비교. 한 필터가 결측 구간(약 50일)을 만든 경우, 같은 유효 구간으로 기준선도 다시 측정해서 증분을 비교했다. 그 결과 앞서 채택한 필터의 증분이 특정 연도에 의존한다는 것을 발견했다. 판정은 번복하지 않고 기록만 했다. 이미 사전등록된 규칙에 따라 결정한 것을 사후 발견으로 뒤집지 않는다.

이어서 조합과 청산 쪽(지표 기반 매수, 상단 청산, 보유 기간 변형)도 같은 방식으로 시험했다. 지표 기반 후보(OBV 등)도 무작위 선정이 더 나은 결과를 냈다.

3. 사용자의 정의가 두 번 바뀌었다#

양봉 기반 선정 요청에서 사용자 정의가 두 번 바뀌었다. 처음에는 “전일 대비 상승”, 다음에는 “시가 대비 양봉(종가가 시가보다 높음)“이었다. composer 지시를 두 번 갱신했고, 프로그램 문서의 개정 이력에 변경을 기록했다. 요구가 바뀌는 것은 정상이고, 중요한 것은 결과를 본 뒤가 아니라 본 이전에 바뀌었다는 사실을 기록으로 남기는 것이다.

4. 처음 살아남은 후보와 그 처리#

유니버스를 7개로 나눠 평가한 회차에서, 특정 풀 두 개가 G1 사전등록 기준을 통과했다. 스트레스(실제에 가까운 비용, 국면 무시, 고가 우선 경로) 아래에서는 한 풀만 살아남았다. 그러나 생존 편향과 다중 비교 위험이 있어서 OOS는 열지 않고 사용자 승인을 기다렸다. 이어서 인접 8칸의 고원을 확인했다(8칸 모두 통과). 그다음 열람 전 기준을 PROGRAM-u6-g2.md로 먼저 쓰고 OOS를 열었다.

결과는 FAIL-G2였다. 수익 팩터 중앙값과 production 비용 기준 모두 1.0 미만이었고 낙폭이 컸다. 연구 중 가장 유망했던 후보를 폐기했다. 고원이 있고 G1을 통과했어도 OOS에서 무너질 수 있다는 것이 다시 확인되었다.

5. 저변동 월간 리밸런싱: 조건부 통과#

사용자가 새 전략 개발을 요청했다. 방향을 묻고(저변동 분산 선택) 단면 스캔을 23개 지표로 확장해 lowvol_monthly를 TDD로 구현했다. 첫 실행은 0건이었다. 거래대금 열이 누락되었다. 고쳐서 재실행하자 창 길이별 시험에서 G1을 조건부로 통과했다.

이후 단계는 이렇다.

  1. 창 연장: 정점은 중간 길이에 있었다. 연구 설정을 그 값으로 갱신.
  2. 국면 사이징 분해: 낙폭 감소의 출처가 특정 연도의 일부 분기임을 도구(연도·분기 비교)로 확인했다. 계수 고원은 인접 8칸 중 7칸 통과.
  3. OOS 두 번째 개봉: 열람 전 기준 문서(PROGRAM-lowvol-g2.md, 오염 고지와 청산 사유 해석 고정)를 쓰고 열었다. 기준 전부 통과해 **조건부 통과 후보(PASS-L2)**가 되었다. 지수 대비 못 미치고 유의성이 약하다는 점을 결과에 명시했다.

이 후보를 모의 관측 모드로 이식했다. 상위 200 거래대금 유니버스를 추가하고, 국면 사이징을 전략별 regime_factor로 옮겼다(사이징, 진입 심사, 전략 설정, 런타임, 백테스트, 웹 전부). 서버의 덮어쓰기가 전략 수 상한을 걸고 있어서 공용 한도 상향은 사용자 결정으로 남겼다. 관측용이라 실전과는 무관하다.

6. 퇴직연금 매매일지: 사용하려던 API가 틀렸다#

퇴직연금 계좌의 매매일지를 만들기 위해 체결 내역 API를 먼저 구현하고 배포한 뒤 프로브로 확인했다. 이 API는 항상 빈 응답에 같은 연속 키를 반복해서 쓸 수 없었다. 대신 잔고 조회 응답에 종목별 오늘 매수·매도 수량과 요약 금액이 있고 사용자의 실제 매매와 일치했다. 체결 API 상수와 프로브를 삭제하고 잔고 기반으로 교체했다. 배포 후 요약 금액이 손익 요약 필드와 일치함을 확인했다.

이어서 코드 리뷰 지적을 처리하며, 보유 목록에 없는 종목(당일 사고 전량 판 종목)의 매수금액이 남은 종목에 배분되는 문제를 막았다. 수량 × 현재가 추정치가 가격제한폭(×1.3)을 넘는 몫은 “미확인” 줄로 분리하고, 실현 손익 계산이 그 줄을 건너뛰게 했다(짝지어 손익이 지어지는 것을 방지). 리뷰 지적 9번은 오탐이었다. 스크리닝은 거래일 장 전 1회 작업이어서 캐시할 이유가 없었다. 지적을 모두 받아들이는 대신 검토 후 근거와 함께 반려했다.

단면 진단 스크립트에서도 하나 고쳤다. 신호일이 구간 끝을 넘는 데이터가 쓰이는 누출이었다. 적재 상한을 구간 끝으로 맞추고 신호일은 끝 전날까지, 수익률은 t+h <= end만 쓰게 했다. 기존 진단을 재계산하니 값이 소수점 둘째 자리 안에서 움직였고 결론은 같았다.

정리#

배운 점: 한 번에 하나만 바꾸면 무엇이 효과가 있었는지 알 수 있다. 그리고 판정이 모호해지는 이유는 대개 도구의 출력(반올림, 열 위치, 하위 프로세스 옵션)에 있다. 연구 결과를 의심하기 전에 측정 도구부터 의심한다. 마지막으로, 사전등록된 규칙에 따라 결정한 것은 나중에 더 좋은 설명이 나와도 번복하지 않고 기록만 한다.
